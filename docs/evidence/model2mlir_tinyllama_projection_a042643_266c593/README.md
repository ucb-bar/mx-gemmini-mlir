# TinyLlama model2MLIR projection stripe on MX Spike

This archive binds `matmul_1`, the layer-0 `q_proj` in the reduced TinyLlama
[full-model capture](../full_model_compile_preflight_a042643_748b984/README.md),
to actual operands tapped from a two-layer random-weight TinyLlama forward.
The selected source contraction is 8×2048×2048. The compiler quantizes all
2048 K elements, pads the eight token rows to DIM16, and issues one 32-column
output stripe. The object contains no operands or golden. A standalone RV64
ELF linked that object and matched the independent MX hardware arithmetic
model on pinned Nicolas Spike: **512/512 BF16 values**, including **256 real
model values** and 256 padded-row values. The live PyTorch f32 output for the
same stripe differs from the MX BF16 result by mean absolute error 0.04424946
and maximum absolute error 0.21039677; this is a precision observation, not
a PyTorch-equivalence acceptance threshold.

The [summary](summary.json), [operand receipt](input_receipt.json),
[payload](bundle/manifest.json), [physical program](object/physical_program.json),
[object manifest](object/object_manifest.json), [ELF receipt](run/artifact_manifest.json),
and [Spike log](run/spike.log) bind the graph site, data hashes, profile,
toolchain, object hash, and complete output comparison. The checked payload
bytes and golden are included in `bundle/`; the complete unquantized model
weights are regenerated by the input recipe below. No pretrained checkpoint
or whole-model executable is claimed.

Reproduce with Python containing PyTorch, Transformers, MXQuant, xDSL, and
model2MLIR. `M2M` must contain the committed model2MLIR `a042643` source
closure; `MXQ` is MXQuant `b4af543`; `RTL` is Nicolas RTL `266c593` with
its pinned Spike extension; `RADIANCE` contains the pinned host arithmetic
model. Put temporary outputs in your managed task's `.tmp/`:

```sh
python -m tools.prepare_tinyllama_projection_inputs \
  --model2mlir-root "$M2M" --out-dir "$TASK_DIR/.tmp/tinyllama-inputs"
python -m tools.qualify_model_projection \
  --full-model-mlir docs/evidence/full_model_compile_preflight_a042643_748b984/tinyllama.mlir.gz \
  --site-region matmul_1 --row-count 8 --column-count 32 --tile-k 128 \
  --activation-npy "$TASK_DIR/.tmp/tinyllama-inputs/activation.npy" \
  --weight-npy "$TASK_DIR/.tmp/tinyllama-inputs/weight.npy" \
  --model2mlir-root "$M2M" --mxq-root "$MXQ" \
  --reference-root "$RADIANCE" \
  --profile profiles/gemmini-mx-cleanup-266c593/MxGemminiRocketConfig.json \
  --rtl-root "$RTL" --riscv-root "$RISCV" --mx-opt "$MX_OPT" \
  --out-dir "$TASK_DIR/.tmp/tinyllama-qproj-stripe" --run-spike
```

This step establishes model2MLIR site selection, model operand capture,
BF16-to-MX quantization, typed resource binding, physical lowering, object
emission, linking, and complete stripe execution. The remaining 63 stripes of
this one projection and every other operation in the model need whole-program
placement, shared buffers, host operations, and session state before a
full-model compile succeeds.
