# Four-checkpoint VPU softmax boundary audit

The [summary](summary.json) records the actual source MLIR softmax tensor
boundaries for the four captured first stages and the pinned Nicolas MX+VPU
profile. It was generated by `audit_softmax_boundaries` in
[`merlin_vpu_inventory.py`](../../../mx_gemmini_support/merlin_vpu_inventory.py)
using Merlin's target-neutral linalg inventory. Each model row binds the
capture `model.mlir` SHA256 and the selected profile SHA256 without publishing
checkpoint data or token inputs.

All 104 captured regions have f32 rank-four input and output tensors, so none
matches the selected profile's direct BF16 rank-two VPU softmax contract. They
remain explicitly host-owned. The rank-three tensors previously reported for
the language models are reduced max/sum intermediates. The model builder now
records this inventory and rejects a directly matching BF16 rank-two softmax
if it lacks integrated VPU lowering, preventing silent host fallback.

This is a structural placement audit. It does not convert f32 scores to BF16,
tile VPU rows, execute a model softmax on the VPU, or establish numerical
equivalence for the conversion.
